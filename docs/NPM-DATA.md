# npm data prototype

`createNpmService` implements an original adapter for the public npm registry. It uses bounded latest-version metadata (falling back to package metadata on a missing latest tag) and the npm downloads point API, with the prior 30 complete UTC dates, inclusive. Scoped identities are preserved and encoded as a single URL component. Only the public npm registry's canonical HTTPS URL and its equivalent trailing-slash/default-port forms are accepted. Redirects are never followed. It does not download or run packages.

The checked-in `seed-1` corpus has 16 manually selected names. It is development data, not a representative or exhaustive registry snapshot. Local unrestricted Damerau–Levenshtein distance selects at most five candidates, using the scoring engine’s length-aware thresholds and separate scope and basename comparisons. This is a bounded brute-force scan of the seed, not an index suitable for a full registry. Corpus selection, provenance, coverage, recall, and maintenance remain launch gates.

The local disk cache stores successful metadata, confirmed metadata 404s, and download observations for 24 hours, shared across checks and candidate appearances. Raw downloads include the date interval in their key. A cached snapshot pins its original interval until its earliest observation expires; therefore midnight does not cause a refresh. A missing package remains undetected for up to 24 hours after publication. Errors are unknown, never confirmed absence; they have a one-minute backoff, extended by Retry-After up to 24 hours. Cache and coordinator errors fail closed. Snapshots record observations and expiration; no stale fallback is implemented.

An exclusive filesystem lease and in-process promise coalescing reduce duplicate work on one host. Lease expiry and recovery are best effort: filesystem lease recovery lacks a transactional compare-and-delete and cannot guarantee correctness during a simultaneous expiry/reclaim race. This is **not distributed hosting ready**, and does not establish the plan's shared hosted 24-hour guarantee. Use a transactional shared database/coordinator with ownership-checked leases before deployment. Waiters time out after about five seconds. Cache state and budget are not shared between hosts. The default cache is `.cache/npm` under the working directory; configure a durable cache directory appropriate to the host. Cache hits retain the original assessment time and observation timestamps, so consumers can calculate their age.

Each service instance has a lifetime upstream request budget (default 100) and a maximum of four simultaneous requests; it fails cold observations closed when exhausted. These limits are per process/instance, not a rolling global budget or per-client limit. There is no circuit breaker, periodic budget reset, or abuse protection across processes. A production deployment needs shared rate limits, a circuit breaker, access controls and operational monitoring. Requests time out after three seconds, response bodies are capped at 2 MB, and errors have a short backoff. These constraints may yield partial results for legitimate unusually large packages. No live registry load test or browser CORS validation is implied.

The prior [pkgguard audit at commit 53dadd7](https://github.com/rxslice/pkgguard-API/tree/53dadd7ad16dcc99e5e19e135447f2ffb02e1df3) informed the plan; this adapter is original and copies no upstream implementation.
